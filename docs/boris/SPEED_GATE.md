# Главное препятствие: скорость

Замер 01.11.2026, RTX 5090, Windows x64, настоящий режим `--live`, форма 131072x131072x4096, `mma-int8`, нагрузка 100%.
Пул локальный (127.0.0.1) со сложностью Kryptex 2097152; наружу ничего не отправлялось.
Воспроизвести: `python tools/boris-live-loopback.py --seconds 240`.

| | TH/s | Один share (сложность 2097152) |
|---|---|---|
| Live worker, по всему времени (1969 тайлов/с) | 0,001 | ~100 дней |
| Live worker, только время работы карты (18,4 с из 240) | 0,013 | ~8 дней |
| Экспериментальная сетка, по всему времени | 0,055 | ~45 ч |
| Экспериментальная сетка, только время работы карты | 0,59 | ~4 ч |
| Обычные майнеры на RTX 5090 (страница устройства Kryptex, чужая цифра) | 340-400 | ~25 с |

Расчёт: один тайл = 524288 MAC, пул зачитывает `diff x 2^32` MAC за share, 1 TH/s = 10^12 MAC/s.
Карта потребляла до 100 Вт из 575: основное время уходит на проверку каждого тайла на CPU, а сам наш GPU-код не использует TMA.

**Вывод: майнинг в панель не подключён.** `boris_pearl/live.py` проходит пул, TLS, задания и остановку, но share от настоящего
пула не получен, а при такой скорости работа бессмысленна.

## Что нужно

В `cuda/gemm/gemm_tma.cuh` уже есть быстрое ядро этого проекта: 73,9 TH/s на GB10 при ~67 Вт (`docs/benchmarks/20260926-2000mhz-sustained.md`).
Оно собрано только под `sm_121a`. Для RTX 5090 (`sm_120`) нужен CUDA Toolkit 12.8 или новее, здесь стоит 12.4, и порт его хоста на Windows.

Критерий готовности: не меньше 300 TH/s на RTX 5090, заявленных пулом за 6+ часов, и отказы около 0. До этого репозиторий остаётся приватным.
